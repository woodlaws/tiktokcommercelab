# 커머스 인사이트 작성 가이드

## 콘텐츠 추가 위치

현재 원문 콘텐츠는 `lib/site-data.ts`의 `posts` 배열에 추가하고, 공개 메타데이터는 `lib/insights-data.ts`의 `migrations`에 연결합니다.

1. `posts`에 고유한 영문 `slug`, 제목, 요약, 발행일, 읽기 시간, 본문, 핵심 요약과 출처를 작성합니다.
2. `migrations`에 같은 slug를 등록하고 1개의 카테고리와 1개 이상의 태그를 지정합니다.
3. 초안은 공개 배열에 넣기 전에 별도 문서에서 관리하거나 `PostStatus`를 `draft`로 설정한 신규 데이터 구조로 이전합니다.
4. 검토가 끝난 콘텐츠만 `published` 상태로 노출합니다.

## 권장 글 구조

- 제목: 검색 질문을 자연스럽게 포함하고 과장하지 않습니다.
- 요약: 120~160자 내에서 글의 답을 먼저 제시합니다.
- 핵심 요약: 독자가 30초 안에 판단할 수 있는 3개 문장으로 작성합니다.
- 본문: 기준 → 준비 → 실행·개선 순서로 작성합니다.
- 출처: 공식 문서의 제목, 발행일, 확인일과 URL을 기록합니다.
- 업데이트: 정책이나 기능이 바뀌면 `updatedAt`을 실제 수정일로 변경합니다.

## SEO·GEO·AEO 체크

- 게시물당 1개의 주 카테고리만 사용합니다.
- 관련 세부 주제는 태그로 연결합니다.
- 첫 문단에서 질문에 직접 답하고, 확인된 사실과 의견을 구분합니다.
- 수치·정책·기능은 원 출처를 확인하고 근거 없는 성과를 만들지 않습니다.
- 제목 체계는 H1 1개, 주요 질문은 H2로 유지합니다.
- 발행일, 수정일, 작성 주체와 출처를 항상 표시합니다.
- 관련 글과 전환 CTA가 문맥상 자연스럽게 이어지는지 확인합니다.

## 발행 전 확인

`pnpm lint`, `pnpm typecheck`, `pnpm build`를 실행하고 상세 URL, 카테고리 URL, 태그 URL, RSS와 사이트맵에 글이 포함됐는지 확인합니다.
