# 통합 문의 저장 연결 가이드

현재 프로젝트에는 실제 데이터베이스, 이메일 전송 서비스 또는 기존 웹훅이 없습니다. 따라서 `/api/leads`는 클라이언트와 서버 검증을 통과한 후에도 `503 not_configured`를 반환하며 접수 완료를 표시하지 않습니다.

## 실제 접수를 활성화하기 전에 필요한 운영 결정

1. 저장 대상: 기존 CRM, 내부 데이터베이스 또는 운영 중인 상담 시스템
2. 운영 주체의 정확한 상호·연락처
3. 개인정보 보유 기간과 파기 기준
4. 담당자별 접근 권한과 열람 기록 정책
5. 문의 유형별 담당자와 알림 경로
6. 장애·중복 접수·삭제 요청 처리 절차

새로운 외부 서비스는 임의로 선택하지 않습니다. 운영자가 사용할 기존 시스템을 결정한 후 연결해야 합니다.

## 서버 연결 위치

`lib/server/lead-storage.ts`의 `persistLead()`만 교체합니다. 관리자 키와 웹훅 시크릿은 Vercel 서버 환경변수로 관리하고 `NEXT_PUBLIC_` 접두사를 사용하지 않습니다. 클라이언트 코드, Git, 로그와 응답 본문에 비밀값을 포함하지 않습니다.

저장 성공과 영구 리드 ID가 실제로 확인된 경우에만 다음 형태를 반환합니다.

```ts
{ ok: true, leadId: "저장소가 발급한 ID" }
```

시간 초과, 부분 실패, 알림만 성공한 경우에는 성공으로 반환하지 않습니다.

## 현재 포함된 보호 장치

- 클라이언트와 서버의 공통 필드 검증
- 동일 출처 요청 확인
- JSON 요청 크기 제한
- 허니팟 필드
- 최소 입력 시간 확인
- IP 기반 단기 요청 횟수 제한
- 응답과 런타임 로그에 개인정보 미출력
- 개인정보가 포함될 수 있는 referrer query 제거
- 파일 첨부 비활성화

서버리스 인스턴스 메모리 기반 요청 제한은 기본 보호 장치일 뿐 전역 방어가 아닙니다. 실제 저장 연결 시 Vercel Firewall 또는 운영 중인 중앙 rate-limit 저장소 정책을 함께 결정해야 합니다.
